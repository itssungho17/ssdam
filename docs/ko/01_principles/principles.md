# 📜 SSDAM 원칙

## 🎯 목표

SSDAM 원칙은 시스템의 설계, 확장, 운영 전반에서
**반드시 유지되어야 하는 불변 규칙**을 정의한다.

이 문서는 다음을 제공한다:

- SSDAM 호환성 판단 기준
- 설계 및 확장 시 의사결정 기준
- 구조 드리프트 방지 규칙
- 사람 / 에이전트 협업 공통 규약

---

## 🧱 원칙 1 — 스테이지는 최상위 단위이다

SSDAM에서 **스테이지는 최상위 목적 단위**이다.

- 작업 / 동작 / 단계의 상위 개념
- 진행 단위가 아니라 **목적 단위**
- 스테이지 간 이동은 상태 전이

**불변 규칙**

- 스테이지는 단일 목적을 가져야 한다
- 스테이지는 명확한 종료 기준을 가져야 한다
- 스테이지는 검증 가능한 산출물을 생성해야 한다

**안티패턴**

- 다중 목적 스테이지
- 종료 기준 없는 스테이지
- 산출물 없는 스테이지

---

## 🧩 원칙 2 — SOLID 준수 스테이지 설계

모든 스테이지는 SOLID 원칙을 따른다.

| 원칙 | SSDAM에서의 해석 |
|------|------------------|
| **단일 책임** | 하나의 명확한 목적 |
| **개방/폐쇄** | 구조 안정 + 확장 가능 |
| **리스코프 치환** | 입력/출력 계약 유지 |
| **인터페이스 분리** | 최소 계약 정의 |
| **의존성 역전** | 구현이 아닌 계약 의존 |

**불변 규칙**

- 목적 혼합 금지
- 계약 없는 스테이지 금지
- 구현 종속 스테이지 금지

---

## 🔄 원칙 3 — 산출물 기반 진행

SSDAM에서 진행은 활동이 아니라
**산출물 생성 및 검증으로 정의된다.**

**규칙**

- 실행 ≠ 진행
- 산출물 존재 ≠ 완료
- 체크포인트 통과 = 진행

**불변 규칙**

- 모든 스테이지는 산출물을 생성해야 한다
- 산출물은 검토 가능해야 한다
- 산출물은 평가 가능해야 한다

**근거**

활동 중심 진행은 착시를 만든다.
SSDAM은 이를 산출물 중심 구조로 차단한다.

---

## ✅ 원칙 4 — 근거 기반 의사결정

SSDAM에서 모든 판단은
**근거로 정당화되어야 한다.**

**규칙**

```
의사결정 → 반드시 근거 필요
```

**불변 규칙**

- 근거 없는 통과 금지
- 근거 없는 실패 금지
- 근거 없는 평가 무효

**근거 예시**

- 테스트 결과
- 정적 분석 리포트
- 리뷰 기록
- 시뮬레이션 로그
- 정책 검증 결과

---

## 🚦 원칙 5 — 체크포인트 권한

체크포인트는 상태 전이를 통제하는
**유일한 판정 메커니즘**이다.

**규칙**

- 통과 / 실패만 존재
- 조건부 통과 금지
- 암묵적 통과 금지

**불변 규칙**

- 스테이지 종료는 체크포인트로만 선언
- 판정 기준은 사전 정의
- 판정 기록은 보존

**안티패턴**

- "일단 다음으로 진행"
- "문제 없어 보임"
- "추후 확인 예정 통과"

---

## 🔁 원칙 6 — 실패는 설계된 이벤트이다

SSDAM에서 실패는 예외가 아니라
**설계된 상태 전이 이벤트**이다.

**규칙**

```
실패 → 기록 → 근거 보존 → 회복
```

**불변 규칙**

- 실패 은폐 금지
- 실패 무시 금지
- 회복 없는 실패 금지

**실패의 의미**

실패는 시스템 붕괴가 아니라
**품질 보호 메커니즘의 정상 동작**이다.

---

## 🔗 원칙 7 — 종단간 추적성

SSDAM은 모든 흐름을 다음 체인으로 연결한다:

```
요구사항
→ 스테이지
→ 실행
→ 산출물
→ 평가
→ 근거
→ 체크포인트
```

**불변 규칙**

- 추적 체인 단절 금지
- 변경 시 이력 보존
- 역추적 가능성 유지

**시스템 효과**

- 의사결정 감사 가능
- 변경 영향 분석 가능
- 실패 원인 분석 가능
- 에이전트 판단 검증 가능

---

## 🤖 원칙 8 — 사람 / 에이전트 책임 모델

SSDAM은 사람 / 에이전트 공존을 전제로 한다.

**규칙**

- 에이전트 = 역할 수행자
- 사람 = 책임 소유자

**불변 규칙**

- 최종 책임은 사람
- 에이전트 판단 재정의 가능
- 고위험/고불확실성 → 사람 우선

**에이전트 제약**

- 평가 결과는 신뢰도 포함
- 불확실성 메타데이터 포함
- 근거 없는 자율 통과 금지

---

## 📐 원칙 9 — 결정적 흐름

SSDAM은 **결정적 상태 전이 구조**를 유지한다.

**규칙**

- 동일 입력 → 동일 판정 기대
- 판정 기준 명시
- 정책 게이트 명확화

**불변 규칙**

- 모호한 종료 기준 금지
- 암묵적 전이 금지
- 비결정적 게이트 금지

**비결정 요소 처리**

비결정 요소는 다음 방식으로 통제한다:

- 확률적 평가 명시
- 신뢰도/오차 범위 포함
- 사람 체크포인트 승격

---

## 🧩 원칙 10 — SSDAM 호환성 제약

다음 조건 위반 시 SSDAM 확장으로 간주하지 않는다:

- 스테이지 불변 조건 위반
- 산출물 / 근거 제거
- 체크포인트 우회
- 추적성 단절
- 실패 구조 무시

---

## ✅ 요약

SSDAM 원칙은 다음을 강제한다:

- 목적 중심 구조화
- 산출물 기반 진행
- 근거 기반 판단
- 실패의 설계화
- 추적 가능한 변경 관리
- 사람 / 에이전트 협업 안정성

SSDAM은:

> **"무엇을 수행했는가"가 아니라
> "무엇이 검증되었는가"를 기준으로 작동한다.**
