# SSDAM Quickstart — Getting Started with Cursor

This guide is for anyone using SSDAM AgentSkills in Cursor for the first time.

---

## Overview

```
[Setup]  Copy templetes → .cursor/skills + edit package.json
   ↓
[SPEC]  /new-mission  →  mission-spec.yaml            ✅
   ↓
[SPEC]  /new-task     →  task-spec.TSK-NNN.yaml       ✅
   ↓
[EXEC]  /architecture-design  →  architecture-design.TSK-NNN.md   ✅
        /data-modeling         →  data-modeling.TSK-NNN.md         ✅
        /schema-design         →  schema-design.TSK-NNN.sql        ✅
        /backend-design        →  backend-design.TSK-NNN.md        🚧
        /backend-implementation →  code in project_root            🚧
        /frontend-design       →  frontend-design.TSK-NNN.md       🚧
        /frontend-implementation → code in project_root            🚧
   ↓
[Done]  Checkpoint PASS → proceed to next Task
```

✅ Verified &nbsp;&nbsp; 🚧 In development

> At any point, if an output does not match your intent, edit the file and resume from that step.

## Step 1 — Install Skills

Create a `.cursor/skills` folder at your project root, then copy all folders inside `templetes/` into it.

```
your-project/
└── .cursor/
    └── skills/
        ├── new-mission/
        ├── new-task/
        ├── architecture-design/
        ├── data-modeling/
        ├── schema-design/
        ├── backend-design/
        ├── backend-implementation/
        ├── frontend-design/
        └── frontend-implementation/
```

---

## Step 2 — Configure Project Info

Open `.cursor/skills/new-mission/assets/package.json` and update it for your project.

```json
{
    "mission_owner": "Your Name",
    "project_context": {
        "backend_stack": "FastAPI, Python, Pydantic, SqlModel",
        "frontend_stack": "Svelte, TypeScript, TailwindCSS, Vite",
        "database": "PostgreSQL"
    }
}
```

| Field | Description |
|-------|-------------|
| `mission_owner` | Name of the person responsible for the mission |
| `backend_stack` | Backend technology stack |
| `frontend_stack` | Frontend technology stack |
| `database` | Database |

---

## Step 3 — Create a Mission

Type your idea or feature list into the Cursor Agent chat.

```
/new-mission {idea or list of features to implement}
```

**Example:**
```
/new-mission A media file marketplace where users can upload and sell images and videos, and buyers can download purchased files.
```

When complete, two files are created:

```
.ssdam/{workspace-id}/
├── input/
│   └── mission-input.yaml    ← auto-generated by the skill
└── output/
    └── mission-spec.yaml     ← full mission definition
```

If anything looks off, ask the Cursor Agent to revise it or edit the file directly.

---

## Step 4 — Generate a Task Spec

Run the following for each Task in the mission.

```
/new-task @mission-spec.yaml TSK-001
```

When complete, the following file is created:

```
.ssdam/{workspace-id}/output/
└── task-spec.TSK-001.yaml    ← contracts, evaluation criteria, execution plan
```

Open the file and check `execution_plan.steps` — this list defines the skills to run and the order to run them.

---

## Step 5 — Run Execution Skills

Follow `execution_plan.steps` in `task-spec.TSK-NNN.yaml`, starting from `EXEC-01`.

```
/{exec_type} @task-spec.TSK-001.yaml {exec_id}
```

**Example sequence:**
```
/architecture-design    @task-spec.TSK-001.yaml EXEC-01
/data-modeling          @task-spec.TSK-001.yaml EXEC-02
/schema-design          @task-spec.TSK-001.yaml EXEC-03
/backend-design         @task-spec.TSK-001.yaml EXEC-04
/backend-implementation @task-spec.TSK-001.yaml EXEC-05
```

> Only run skills listed in the task-spec. Which steps are included depends on the nature of the task (backend-only, full-stack, etc.).

---

## Step 6 — Mid-Process Corrections

If an output does not match your intent, edit the file and resume from that point. You can go back to any step at any time.

```
Example: the architecture-design output is not quite right
 → Edit architecture-design.TSK-001.md directly
 → /data-modeling @task-spec.TSK-001.yaml EXEC-02  (resume from the next step)
```

## File Location Reference

| File | Path |
|------|------|
| Skill definitions | `.cursor/skills/{skill-name}/SKILL.md` |
| Project config | `.cursor/skills/new-mission/assets/package.json` |
| Mission input | `.ssdam/{id}/input/mission-input.yaml` |
| Mission spec | `.ssdam/{id}/output/mission-spec.yaml` |
| Task spec | `.ssdam/{id}/output/task-spec.TSK-NNN.yaml` |
| Design outputs | `.ssdam/{id}/output/design/{skill-name}.TSK-NNN.md` |
| Schema output | `.ssdam/{id}/output/design/schema-design.TSK-NNN.sql` |
| Implementation code | `{project_root}/` (written directly by the agent) |
